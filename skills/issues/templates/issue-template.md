# Issue Template

This template defines the required structure for all implementation issues in this repository.

Issues generated by AI agents **must** follow this structure exactly.

Each issue should represent **one logical unit of work** that can be completed, tested and reviewed independently.

---

## Context

Briefly explain:

* why this work is required
* which MVP milestone it belongs to
* what capability is unlocked once complete

**Phase:**

---

## Acceptance Criteria

Provide a numbered list of objective, testable outcomes.

Example:

1. The parser interface has been created.
2. The solution builds successfully.
3. Unit tests covering the new behaviour have been added.
4. Existing tests continue to pass.
5. All documentation affected by this change has been updated.

---

## Files Likely Affected

List the files expected to be created or modified.

Example:

```text
src/StatementParser.Application/Interfaces/IStatementParser.cs
tests/StatementParser.Application.Tests/ParserTests.cs
```

---

## Files Not To Touch

List any files or folders that should not be modified while completing this issue.

If there are no restrictions, state:

```text
None
```

---

## Constraints

List any important implementation constraints.

Examples:

* Do not introduce functionality from future milestones.
* Do not add unnecessary NuGet packages.
* Keep parsing and CSV export concerns separate.
* Preserve the existing architecture.
* Maintain backwards compatibility with existing parsers.

---

## Definition of Done

The issue is complete when:

* All acceptance criteria are met.
* The solution builds successfully.
* All automated tests pass.
* No existing functionality has regressed.
* Documentation has been updated where required.
* The implementation is ready for code review.

---

## Notes (Optional)

Any additional implementation notes, assumptions or references that may help the developer completing the issue.
